# Writing Markdown files

Apply these rules to every `.md` file you create or edit: README, plans, docs, ADRs, notes.

## Language

- Documents, code, comments, commits, identifiers: always English, unless the repo already uses another language for docs.
- Never mix languages in one file.
- Keep code, commands, paths, and error text verbatim.

## Structure

1. First line after the title: what this file is for and who reads it.
2. Most important information first.
3. Steps: numbered list, one bounded action per step.
4. Max 5 items per list. If more, split into groups with headers.
5. Tables only to compare options. Bullets max 2 levels deep.
6. Warnings and prerequisites before the instruction, never after.
7. Every command in a code block, ready to copy.

## Sentences (ASD-STE100)

1. Active voice, present tense.
2. One instruction per sentence. Max 20 words (procedures), 25 (descriptions).
3. Paragraphs: max 6 sentences, one topic.
4. One word = one meaning. No synonyms for variety.
5. Max 3 nouns in a row.
6. Keep articles (the, a).
7. No hedges ("perhaps", "might") unless uncertainty is real information.
8. Simple words: "use" not "utilize", "start" not "initiate".

## Do not

- No preamble ("This document describes..."), no recap, no closing summary.
- No marketing words ("powerful", "seamless", "robust").
- No emoji in headers.
